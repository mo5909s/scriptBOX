Documentation: welcome.ps1

Project path: src/welcome.ps1

Purpose: This script launches or reuses Thunderbird, Spotify, and Microsoft To Do, waits until their main windows exist, tiles the three windows across a selected screen, and optionally plays a startup audio file.

1. How the script works

Main execution flow

  1. Reads startup settings such as dry-run mode, timeout behavior, screen index, and audio settings.
  2. Loads small Win32 helpers using Add-Type so PowerShell can call SetWindowPos and ShowWindow.
  3. Resolves installation paths for Thunderbird, Spotify, and Microsoft To Do.
  4. Starts each app if it is not running yet, or reuses an existing process if it is already open.
  5. If not in dry-run mode, waits until each app has a real window handle.
  6. Finds the target screen and tiles the three windows in equal-width columns.
  7. Optionally plays welcome.mp3 or a fallback audio file.
  8. Prints a short success message, or an error if one step fails.

Important functions

FunctionWhat it does
Resolve-ExecutableLooks for an app via Get-Command first, then through known installation paths.
Start-OrReuseProcessReuses an already-running process or launches the application if needed.
Wait-ForMainWindowPolls until a process exposes a real top-level window or until the timeout is reached.
Get-TargetScreenFinds the requested monitor and falls back safely if that screen index does not exist.
Tile-Windows-OnScreenSplits the chosen work area into three columns and positions the windows accordingly.
Play-StartupAudioTries to play welcome.mp3 or startup_audio.wav for a limited number of seconds.

What gets tiled

  • Column 1: Thunderbird
  • Column 2: Spotify
  • Column 3: Microsoft To Do

2. Setup instructions for another user

Prerequisites

  • Windows desktop environment with PowerShell support.
  • Installed applications: Thunderbird, Spotify, and Microsoft To Do.
  • At least one available display.
  • Optional audio file at src/welcome.mp3.
Important: The script is Windows-specific because it depends on user32.dll, window handles, and Windows Forms screen detection. It is not meant for macOS or Linux without a rewrite.

Recommended first test

Use dry-run mode before actually moving windows. This confirms whether the script can find the installed applications.

powershell -ExecutionPolicy Bypass -File .\src\welcome.ps1 -DryRun

Normal run

powershell -ExecutionPolicy Bypass -File .\src\welcome.ps1

Run on another monitor

powershell -ExecutionPolicy Bypass -File .\src\welcome.ps1 -ScreenIndex 0

Run without music

powershell -ExecutionPolicy Bypass -File .\src\welcome.ps1 -SkipStartupAudio

Settings users typically change

ParameterTypical use
-DryRunUse this first to confirm detection of applications without launching or moving anything.
-TimeoutSecondsIncrease if one of the apps starts slowly on the user’s machine.
-PollMillisecondsControls how often the script checks for windows during startup.
-ScreenIndexChoose the monitor used for tiling. The script falls back to a safe screen if the requested index does not exist.
-StartupAudioPathUse a custom audio file instead of the default project audio file.
-StartupAudioSecondsControls how long the startup audio should play.
-SkipStartupAudioDisables audio completely.

How another user should adapt it

  • Install the same three applications or edit the script if they prefer different apps.
  • Run -DryRun first and check whether all three executables are detected.
  • Adjust -ScreenIndex for their monitor layout.
  • Set -SkipStartupAudio if they do not want sound on startup.
  • If their app installs live in other locations, update the candidate paths in the script.

  • The script is tailored to Windows and desktop GUI sessions.

  • Store-installed apps can behave differently depending on Windows configuration.
  • Audio playback depends on available media support in the current environment.

4. Troubleshooting

  • App not found: run with -DryRun and verify the application is installed in one of the expected locations.
  • Window timeout: increase -TimeoutSeconds if the app opens slowly.
  • Wrong monitor: change -ScreenIndex; if the index is invalid, the script falls back automatically.
  • No audio: ensure welcome.mp3 exists or provide -StartupAudioPath.
  • Unexpected layout behavior: some applications resize themselves after launch, which is why the script applies the tile layout twice.
