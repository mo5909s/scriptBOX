Documentation: driverUpdate.sh

Project path: src/driverUpdate.sh

Purpose: This Linux shell script checks trusted driver and firmware update channels, shows what they report, and asks whether to install the available updates. It focuses on safe distro and firmware tooling instead of random download links.

1. How the script works

  1. Detects the distro package backend (apt, dnf, or pacman) if available.
  2. Checks fwupdmgr for firmware updates delivered through LVFS.
  3. Checks ubuntu-drivers for recommended proprietary driver changes on Ubuntu-based systems.
  4. Checks the distro package manager for updates to common driver-related packages such as firmware, Mesa, NVIDIA, Intel, AMD, and X.org driver packages.
  5. Shows the findings and asks whether each update source should be applied.

2. Safe update sources

SourceWhat it coversInstall action
fwupdmgrFirmware updates published through LVFSsudo fwupdmgr update
ubuntu-driversRecommended proprietary drivers on Ubuntusudo ubuntu-drivers autoinstall
Distro package managerInstalled driver-related packages from trusted reposOnly upgrades the matching packages

3. Usage

Basic interactive run:

./src/driverUpdate.sh

List only:

./src/driverUpdate.sh --list-only

Dry run:

./src/driverUpdate.sh --dry-run

Auto-confirm prompts:

./src/driverUpdate.sh --yes

4. Setup instructions for another user

  • Make the script executable: chmod +x ./src/driverUpdate.sh
  • Use sudo rights if updates should be installed.
  • Install optional tools if you want deeper coverage:
    • fwupd for firmware checks
    • ubuntu-drivers-common on Ubuntu for proprietary driver recommendations
  • Run --list-only first if you only want to review what the machine reports.

Ubuntu/Debian example dependencies:

sudo apt-get update
sudo apt-get install fwupd ubuntu-drivers-common

5. Current state

Implemented now:
  • Firmware scan through fwupdmgr when available.
  • Ubuntu driver recommendation scan through ubuntu-drivers when available.
  • Driver-related package update detection through apt, dnf, or pacman.
  • Interactive install prompts for each source.
  • Dry-run and list-only modes.

Known limitations

  • Linux driver delivery is distro-specific. No single command can guarantee every possible vendor driver is covered.
  • The package-manager scan is pattern-based and focuses on common driver-related package names.
  • Some GPU vendors or enterprise hardware vendors may require repository setup or vendor tools that are outside this script.
  • Firmware updates often require a reboot after installation.

6. Troubleshooting

  • No results from fwupdmgr: the tool may not be installed, or the device may not be supported by LVFS.
  • ubuntu-drivers not found: install ubuntu-drivers-common or ignore that source on non-Ubuntu systems.
  • No driver package updates found: this can be normal if the repositories currently offer nothing newer.
  • Permission denied: rerun with a user that can use sudo.
